# Canonical Package Scaffolds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make both package scaffold commands emit the canonical Pandora package manifest.

**Architecture:** Keep manifest creation private to the CLI crate. Construct the canonical `PackageManifest`, serialize it with `toml`, and reuse the same helper from both command handlers.

**Tech Stack:** Rust, Cargo, Serde, TOML

## Global Constraints

- Preserve all public APIs and command names.
- Modify only the `pandora` CLI crate and its tests.
- Keep the change reversible in one implementation commit.
- Do not change package publication or registry behavior.

- [ ] **Step 3: Implement the private serializer**

Add the following private helper near the package command handlers:

```rust
fn package_manifest_toml(name: &str) -> String {
    let manifest = pandora_types::package_format::PackageManifest {
        id: name.to_string(),
        name: name.to_string(),
        version: "0.2.0".to_string(),
        kind: pandora_types::package_format::PackageKind::Gene,
        publisher: "you".to_string(),
        description: format!("A {name} gene"),
        author: "you".to_string(),
        license: "MIT".to_string(),
        pandora_version: ">=1.0".to_string(),
        lifecycle: pandora_types::package_format::PackageStatus::Draft,
        ..Default::default()
    };
    toml::to_string_pretty(&manifest).expect("canonical package manifest serialization")
}
```

Replace both handwritten manifest strings with calls to this helper.
